# Правила работы с Git

## Ветки
- `main` — стабильная ветка. Прямые коммиты в неё запрещены.
- Для каждой задачи создается отдельная ветка от `main`.
- Названия веток: 
  - `feature/<НОМЕР>-<описание>` (например, `feature/TASK-02-db-setup`)
  - `fix/<НОМЕР>-<описание>` (для исправления ошибок)
  - `docs/<НОМЕР>-<описание>` (для документации)

## Коммиты
Номер задачи обязательно указывается в сообщении коммита.
Пример: `TASK-02: добавлены модели базы данных`

## Слияние (Pull Request)
1. После завершения работы над задачей ветка отправляется на GitHub (`git push`).
2. Создается Pull Request (PR) в ветку `main`.
3. В описании PR указывается `Closes #<НОМЕР_ЗАДАЧИ>` для автоматического закрытия задачи в трекере.
4. PR проверяется другим участником команды.
5. После проверки ветка сливается в `main`, а на GitHub нажимается `Delete branch`.
